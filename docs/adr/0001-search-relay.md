# 搜索中转复用现有账户体系，由调用方显式选源

日期：2026-10-29。状态：已采纳并部署到现有 AWS Docker Compose 环境。

在现有 new-api 网关中提供统一的网页搜索 API，首版接入 Tavily、Brave Search 和 Bocha Search，返回网页标题、链接、摘要等结果。AI 生成回答与独立网页抓取／Extract 不属于首版范围。

2026-10-30 扩展百度搜索，按[官方网页搜索接口](https://cloud.baidu.com/doc/qianfan-api/s/Wmbq4z7e5)接入 `baidu-search`。固定使用 `standard` 版与 `baidu_search_v2`，仅请求网页结果，不通过参数切换上游计费档位。渠道 Base URL 为 `https://qianfan.baidubce.com`，程序追加 `/v2/ai_search/web_search`。百度支持 week/month/year 时效过滤，不支持 day，后者在发出上游请求前返回 400；查询原样转发，但百度文档说明只检索前 72 个字符（汉字按 2 计），因此建议使用简短查询。

调用方像调用模型一样显式指定搜索产品，由产品确定搜索源。统一接口规范请求与结果格式，不把不同供应商的搜索质量、能力或价格视为相同。故障切换限于同一供应商的可用渠道，不自动跨供应商选源，也不聚合多家结果。

统一入口为 `POST /v1/search`，`model` 可选 `tavily-search`、`tavily-search-advanced`、`brave-search`、`bocha-search`、`baidu-search`；具体请求与响应见 [OpenAPI](../openapi/relay.json)。后台复用渠道管理与价格设置，增加四类搜索渠道、渠道测试及搜索调用示例。每次价格由管理员配置，不预设销售价格；未配置价格时拒绝调用。

搜索与模型调用使用同一套 API Key、账户余额及 Key 额度管理；搜索产品沿用现有渠道、分组、访问控制和消费记录体系，不建立独立搜索账户或密钥。这样已有模型调用方可以用现有身份接入搜索，同时明确选择所需的信息源。

按搜索源及档位配置每次价格，并沿用分组倍率。成功搜索包含成功返回空结果的情况；最终失败退回预扣额度。同源渠道重试后最终成功仅向调用方收取一次费用，额外上游尝试的成本由平台承担。上游超时不证明上游未收费，因此本地退款与上游成本不能混为一谈。

自动验证使用 HTTP 测试服务，覆盖供应商协议转换、统一 Key 鉴权与产品授权、余额不足、空结果扣费、失败退款、重试单次结算、显式免费价格，以及渠道配置限制。Tavily 的真实公网搜索与按次扣费已验证；2026-10-30 使用同一现有 Key 实测百度和 Bocha，均返回 HTTP 200 与 3 条结果，消费日志分别为 85352、85353，各按当时配置的 $0.001、$0.01 扣费一次，账户余额与 Key 额度变化一致。

部署使用版本 `v1.0.0-rc.47-search.20261030t052558z`，包含百度渠道，只替换应用镜像。部署前完成 PostgreSQL 与应用文件备份，并在隔离副本验证恢复、启动及重启；部署后确认原 PostgreSQL、Redis 容器和数据卷未变，表结构、业务数据及权限规则内容一致。公网新版前端（含百度渠道资源）、搜索鉴权和原 API Key 的模型目录检查通过。搜索供应商密钥及售价仍由管理员配置。

凭据与访问控制参考 [OWASP ASVS 5.0.0](https://github.com/OWASP/ASVS/tree/v5.0.0) 的 2.2.1、2.2.2、6.3.4、8.3.1、16.2.5、16.5.1，以及 [REST Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)。回归验证了服务端输入白名单、缺失 Key 与产品权限拒绝、上游请求不转发调用者凭据、错误及消费日志不泄露上游密钥、拒绝上游重定向。这是本次改动的验证范围，不代表整个应用通过 ASVS 合规审计。
